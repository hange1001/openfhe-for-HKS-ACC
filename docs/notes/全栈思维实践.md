## 一、全栈思维的定义与意义

### 1.1 栈：六层，以及层与层之间的双向流

本项目的栈是这六层。真正要看的不是层本身，而是**层与层之间流动的东西**：

```
          需求 / 约束  向下流                     参数  向上供给
  ─────────────────────────────────────────────────────────────────
  L0 算法    CKKS HKS 公式             →   α, dnum, sizeQl, sizeP 的合法取值域
     ↓
  L1 算子    把公式切成「一次调用算什么」  →   n_op, n_call, V(字节), peak(limb)
     ↓                                       的【符号式】
     ↓                                   ←   约束来自 L3 的阵列形状、L5 的 T_fixed
  L2 调度    循环序 + 存储分配           →   三模型合成 T(N, l, K, dnum)
     ↓                                   ←   约束来自 L4 的片上预算 B
  L3 微架构  PE 阵列 / 蝶形 / 驻留        →   c_op 单价（csynth 周期）
     ↓                                   ←   约束来自 L4 的时序与资源
  L4 物理    时序 / 资源 / 布线           →   f_clk、B_onchip、csynth→上板修正系数
     ↓
  L5 系统    PCIe / XRT / driver        →   T_fixed、BW_eff
```

**左边是需求向下流，右边是参数向上供给。** 两条流都通，这个栈才是活的：向下流决定「每层该做什么」，向上流决定「上一层的模型有没有输入」。

> 出处：推导v1 §1。

### 1.2 定义

**全栈思维 = 让上面那条回路闭合的纪律。** 三个要素：

1. **栈**：L0–L5 六层（§1.1）。
2. **动作**：把「算法推导 → 实现 → 回到测量」走通一遍，**中间不断裂**。注意不是「每层都做过」，而是**每层的结论都能被上一层推出、并向下一层交付**。
3. **判据**：

> **任何一个写下来的数字，都必须能回答「它是哪一层的哪个约束推出来的」。答不上来，它就是拍脑袋常数。**

第 3 条是可操作的，因为它可以当场执行。以本项目最常被引用的 8.229 ms 为例，追溯链应该长这样：

```
  8.229 ms
    │
    ├── 45 次调用 ─────────── L1  由算子账推出
    │
    └── 182.8 μs/call ─────── L5  单次 offload 均值
          │
          ├── 40.6 μs  H2D ──── L5  PCIe 带宽 + 固定开销
          ├── 123.0 μs kernel ── L3  微架构单价 × L4 上板修正系数
          └── 19.2 μs  D2H ──── L5  PCIe

          ⚠ 链在这里断了：三段之和并不是单次调用的墙钟
             （未计入 xrt::bo 分配与两次 host memcpy）
```

一路拆到每一项都落在某层的某个具体约束上为止。**追溯链断在哪里，哪里就是全栈能力的缺口。**

### 1.3 与常见理解的区别

按上面的定义，「全栈」与**知识面的宽度**无关。这个区别值得单独说，因为最容易走的岔路正是把全栈理解成宽度：

```
  ❌ 把「全栈」理解成宽度
       L0    L1    L2    L3    L4    L5
       ✓     ✓     ✓     ✓     ✓     ✓      六层都动过手
                                            但层与层之间没有箭头
       → 每个数字只能事后解释，不能事前预测 =「体力活感」

  ✅ 本文的定义：回路闭合
       L0 ──约束──→ L1 ──约束──→ … ──约束──→ L5
       L0 ←──参数── L1 ←──参数── … ←──参数── L5
       → 每个数字都能报出「哪一层的哪个约束」
```

本项目按宽度标准早就达标——六层都动过手。但真实状况是：**每层各自局部最优，层与层之间的推导链没有人写下来。** 于是每次实测出一个数字，只能事后解释，不能事前预测。**不是干得少，是干的事之间没有连接。**

所以缺的从来不是某一层的知识，而是 §1.1 右边那条**向上供给的回路**：L3 能给出 15,701 cyc，L5 能给出 182.8 μs，但没有一个 L1 表达式把它们乘起来。

### 1.4 意义：五个跨层实例

以下五条都是本项目已经推出的真实结论，共同点是：**单看一层会得出错误或肤浅的判断，跨层才看清真相。** 此处只列结论，推导与数据在第三部分展开。

| # | 跨层结论 | 停在单层会怎样 | 涉及层 · 详见 |
|---|---|---|---|
| 1 | 三策略的排序是 `c_BConv/c_NTT` 的函数，是**平台单价的性质，不是策略的性质**（CPU 与 FPGA 上排序相反，交叉点约 0.3） | 只能说「换个平台结论会变」——是描述不是解释，没有预测力 | L1→L3/L5 · §3.2 |
| 2 | 瓶颈是**系统边界的函数**。HERA 图上没有 PCIe 屋顶，所以它看见的瓶颈是 NTT；画上 PCIe 屋顶才是本项目的 Fig. 1 | 把跨不同边界的 AI 画进同一张 Roofline，得出互相矛盾的瓶颈判断 | L1↔L5 · §3.2 |
| 3 | 跨层的优化收益**不能相乘**：微架构 1.69× 与传输重叠 1.49× 一起做是 **3.06×** 而非 2.52×——`+` 变 `max()` 后不满足乘性分解 | 按单项收益排序，把本该捆绑的两件事拆开先后做，每项收益都被低估 | L3×L5 · §3.2 |
| 4 | 口径错误会**顺着链向上污染**：L5 的一个下界被当墙钟用 → L2 的 Amdahl 分母偏小 → L3 的优化天花板被高估 → 最终改变排期决策 | 以为只是某个数字不准，实际是所有消费它的层一起错 | L5→L2→L3 · §3 |
| 5 | **断链的代价**：一个常数四个取值（PE_PARALLEL）、两次降频零条记录（4ns→5ns→6ns） | 当时都做对了工程动作，只是没写回「为什么」；半年后整批综合报告口径存疑 | L3/L4 · §3 |

前四条讲「跨层能看到什么」，第 5 条是它的反面——**链断掉之后会怎样**。两面合起来，「意义」才不是一句口号。

第 5 条还额外说明了一件事：这些欠账**都不是能力问题**。改并行度、降频跑通，当时每个动作都是对的，**缺的只是把决策写回上一层**。全栈思维在这里的作用不是让你做对，是让你**半年后还能说清当初为什么那么做**——否则后续每一层都在一个失去定义的基础上继续推。

### 1.5 落点：产出的是判断力，不是代码

全栈思维的产出**不是更多的实现**，而是三种换了载体之后仍然成立的能力：

| 能力 | 具体表现 | 本项目的证据 |
|---|---|---|
| **事前预测** | 改动之前就能给出预测值和 ±15% 区间 | 修 OC 的天花板是 8%，OC + 片上驻留是 29%。**8% 本身就是一个诊断结果**——它说明修 OC 没往主要矛盾上使劲 |
| **一句话杀死一个设计点** | 不必跑实验就能排除方案 | 「tower-major + 全补基输出：既不省缓冲也不省重取，直接排除。」用一句话杀死一个点，比跑一次实验便宜 |
| **迁移** | 换平台、换参数，同一套推导仍成立 | 模型自变量是 (N, l, K, dnum, PE, f, BW, T_fixed)，全部是自变量；**模型里若出现 `if (strategy == OC)`，那它就是查找表不是模型** |

判据也随之改变：从「有没有新颖性」改成——

> **每一个数字，能不能说清它是哪一层的哪个约束推出来的。**

这条判据在写作本节的过程中就被触发了一次：`task.yaml` 的 `context` 写着「（**实测** 8.04/8.23/8.46 ms 印证）」，而同一文件的 `completed_tasks` 与推导v1 §4 都明确记载，这套数字是**控制模型的输出而非实测**。同一个仓库、同一份文件内部，一个数字有两种身份。

**这不是笔误的问题。**「实测」意味着它可以用来验证模型，「模型输出」意味着它不能——**用模型的输出去验证模型，是自洽，不是验证。** 一个词的差别，决定了这个数字能不能作为证据使用。

全栈思维的日常形态，就是这一类检查。

## 二、相关材料学习

### 2.1 原则：材料按问题组织，不按学科组织

材料清单最容易写成一份学科目录——并行编程、体系结构、编译优化各来几本。这样排出来的书单，读完之后不知道该用在哪。

本项目用的是另一种排法：**每份材料绑定一个「读完必须能回答的项目内问题」。答不出，就是没读进去，不往下走。**

```
  ❌ 按学科组织                        ✅ 按问题组织
     并行编程 ─┐                          空白①「延迟 vs 吞吐」
     体系结构 ─┼→ 读完 → ？                    ↑ 绑定
     编译优化 ─┘                          CS149 L1–2 + Amdahl (2008)
                                                ↓ 验收
     读完不知道用在哪                     「8.229 ms 是墙钟还是记账加总？」
                                          答不出 = 没读进去
```

这不是学习技巧，是**第一部分那条判据在学习上的投影**：数字要能报出「哪一层的哪个约束」，材料就要能报出「解决了哪个空白」。两者是同一条纪律。

由此还得到一条硬规定：**拿不到的文献，不得作为任何推导或数字的依据。** 出处不可核对，等同于拍脑袋常数。

### 2.2 先核查，再补课

起因是一份导师给的算子优化通用检查清单（并行性 / 数据依赖 / 延迟 vs 吞吐 / 计算 vs 带宽 / tiling / reduction·同步·负载均衡 / Amdahl·Roofline，外加「从系统框图加 memory access 找瓶颈」）。

第一眼像是「要从头学一门课」。**核查之后不是。**

```
  导师清单（8 大项 / 展开 18 个细项）
      │
      ├── ✅ 有实有名 ×9   结论已推出且已用通用术语表述 → 直接引用，不必重做
      ├── 🟡 有实无名 ×6   结论已推出，只以项目内部语言存在 → 补一句定义，成本≈0
      └── ❌ 空白    ×3   从未进入任何模型或笔记 → 真工作量
                          ① 延迟 vs 吞吐  ② 负载均衡  ③ 分层 Roofline
                          合计约 1.5 天，不是一学期
```

8 大项里 5 项早已答出，而且**推得比教科书例子深**——依赖表、peak 的循环序推导、stationary 分类的同构识别，都是自己推的。问题只在于它们**只以项目内部语言存在**，外部读者（审稿人、面试官、同组同学）一条也看不见。

**所以补课的第一步不是读书，是核查。** 清单不是课程大纲，是**检查清单**；先分清哪些是「已做但没贴标签」，哪些是真空白，才知道那 1.5 天该花在哪。

Bailey 那三条值得抄在这里，因为它们全部命中本项目：**分项加总冒充墙钟、两点拟合冒充标定、共享常数的自洽冒充验证。**

D4–D5 标 ★★ 的理由：要建的模型（循环序 → 延迟 + 资源 + 能耗）**本质上就是 Timeloop**。读它是为了偷抽象与记账口径，不是为了用工具——本项目的算子是 BConv + NTT，不是 CONV。

D7 标 ★ 的理由：它是「从系统框图找瓶颈」这条要求在本领域的标准答案，也是第一部分实例 2（瓶颈是系统边界的函数）的直接输入。**但 F1 的 PDF 当前拿不到**——按 §2.1 的硬规定，在拿到之前它不能作为任何结论的依据。备选是 Theodosian (2025)，主题同样是「系统框图 + memory hierarchy 找瓶颈」，且比 F1 新四年。

### 2.4 学习方式本身也要对账

三条元教训，都是在读材料的过程中撞出来的。

**① 能复述 ≠ 能推导。** 一次闭卷小测只得 0.5/5，诊断出的病根不是没读，是**「AI 推导、用户旁观」**——推导过程看着顺理成章，但从未自己走过一遍。处方是角色翻转：**改成「你画我改」**，先自己产出，再拿去批改。这一条直接决定了后续材料的用法：不是读完打钩，是读完先自己推一遍。

**② 组织形式会反过来吃掉内容。** 书单初稿按「天」排，主题定成「延迟 vs 吞吐 + Amdahl」之后，CS149 的《Work Distribution》与《Locality, Communication and Contention》两讲不属于当天主题、又没有自己的一天，就在排期时被挤掉了——**而这两讲恰好覆盖三个真空白中的两个。**

这与本项目另一处错误是同一类：按「列」记录实验表，让两条不同源的路径并排冒充同源。**组织形式一旦定死，就会开始决定内容的去留。**

**③ 相反方向的偏差必须分开查。** 判断某个数字是上界还是下界时，初稿只想到「重叠会让加总高估」，就下了「是上界」的结论；实际情况是没有任何重叠、但漏了计时，所以是**下界**——方向正好反了。**两个方向的偏差来源要分别列出来逐个排除，只想到一个就下结论，结论会反。**
