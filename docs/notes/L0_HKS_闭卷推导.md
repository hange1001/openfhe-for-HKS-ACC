## 1. 问题设定：key switching 要算什么

CKKS 密文 c = (c0, c1)，c0 + c1·s ≡ m + e (mod Q_l)。
换密钥 s → s′，需要构造 c′ 使 c′0 + c′1·s′ ≡ c0 + c1·s (mod Q_l)，噪声增幅可控。

思路：把 c1 拆成小份（digit），每份乘一份 evk。evk_j 加密的是 P·s′
（P 是辅助模数积，P 加权嵌在 evk 里而不是乘在 digit 上——这是 OpenFHE/eprint 2021/204
附录变体；Han-Ki 原文是带权分解，两者等价，见指南 §Step 1 修正记录）。于是乘出来的是
P·c1·s′，最后 ModDown 除以 P 还原。

digit 分解（tower 不相交切分）：active tower 集合 {0..l−1} 按 α 个一组切成 dnum 组：

    Q_j = ∏_{i ∈ digit j} q_i ,  c_{1,j} = c1 在 digit j 的 tower 上的投影

恒等式（整系数多项式层面）：

    c1 ≡ Σ_j CRT_j(c_{1,j}) · (Q_l / Q_j) · (Q_l / Q_j)^{-1}  (mod Q_l)      …… 形式上

但 HKS 不显式重构大整数，而是把「重构 + 换基」合并为 ModUp。噪声预算：digit 越小
（dnum 越大、α 越小）噪声越好，代价是 BConv 次数和 evk 份数增加——这是 L1 层的设计空间，
L0 只负责把每一步的代数恒等式和误差界钉死。

## 2. 从 CRT 推出 BConv（题 1 核心）

### 2.1 精确 CRT 重构

设基 A = {a_1,…,a_m} 两两互素，Â = ∏ a_i，Â_i = Â/a_i。
x 在基 A 上的中心剩余为 x_i ∈ (−a_i/2, a_i/2]。CRT 重构：

    v = Σ_i [ (x_i · (Â_i^{-1} mod a_i)) mod a_i ] · Â_i  ≡ x (mod Â)
              └──────────────┬──────────────┘
                   【系数必须先对 a_i 约减】见 2.1.1

即 v = x + u·Â，u ∈ Z。

#### 2.1.1 为什么系数必须先 mod a_i（两个理由，缺一不可）

**理由 1（位宽）**：Â_i 是 m−1 个 60-bit 素数的乘积（m=8 时 420 bit），64-bit 硬件
不能直接乘。约减后系数落回单字。

**理由 2（误差界）**：关键是恒等式 **a_i · Â_i = Â**（Â_i 定义的移项）。
设 x_i·(Â_i^{-1} mod a_i) = k·a_i + r，则

    x_i·(Â_i^{-1})·Â_i = k·(a_i·Â_i) + r·Â_i = k·Â + r·Â_i
                              └───┬───┘
                          = Â，mod Â 后整项消失

→ **约减不改变 mod Â 的结果，但把界压小 2^60 倍。**

两种界对比（中心剩余口径：|r| ≤ a_i/2，|Â_i^{-1} mod a_i| ≤ a_i/2）：

| | 单项上界 | |u| |
|---|---|---|
| **约减后** | \|r·Â_i\| ≤ (a_i/2)·(Â/a_i) = **Â/2** | **≤ m/2** |
| 不约减 | (a_i/2)²·Â_i = a_i·Â/4 | ≤ (1/4)Σa_i ≈ m·2^58 |

**差 2^60。** 不约减的话 P 要比 Q_j 大 60+ 比特 → HKS 直接不可用。
（此处是 2026-08-07 修订：初稿的 |v| 界用的是未约减版本，与 2.3 的 α/2 差 2^60，
中间正是缺了这一步。）

### 2.2 近似基转换（BConv）

要把 x 表示到新基 B = {b_1,…,b_k}（与 A 互素）。精确做法：先算大整数 v，再取 mod b_j。

**必须分清两个 mod——「近似」只跳过其中一个**：

| mod | 做不做 | 作用 |
|---|---|---|
| **mod Â**（对 Â 的大整数归约） | **跳过** ← 这是「近似」的唯一来源 | 精确性；跳过它就带上 u·Â 误差 |
| **mod a_i**（系数上的约减） | **必须做**（见 2.1.1） | 位宽 + 误差界；跳过它误差涨 2^60 倍 |

于是：

    BConv(x)_j = [ Σ_i ( (x_i · (Â_i^{-1} mod a_i)) mod a_i ) · (Â_i mod b_j) ] mod b_j

**BConv 求和式**（这就是要徒手写出的式子；每个系数位置独立成立，以下省略系数下标）：

    ŷ_j = [ Σ_{i=1..m} ( x_i · QHatInv_i mod a_i ) · QHatModp_{i,j} ] mod b_j
    其中 QHatInv_i = Â_i^{-1} mod a_i ，QHatModp_{i,j} = Â_i mod b_j

### 2.3 「近似」误差界

跳过 mod Â 的后果：BConv 输出与精确值之差恰是 Â 的**整数倍**：

    ŷ_j ≡ x + u·Â (mod b_j)，  |u| ≤ m/2        ← 由 2.1.1 的【约减后】界给出

对 ModUp 的应用（A = Q_j，m = α_j 个 tower，q_i ≈ 2^60）：

    **每系数误差 = u·Q_j，|u| ≤ α/2 = O(α)**
    即「BConv 溢出误差 ~ α·Q_j」——task.yaml step 1.1 提示里 a·Q_j 的 a 就是 α（digit 宽度）。

> **界的形式随剩余约定变化**：中心剩余给 |u| ≤ m/2；非中心（[0,a_i) 口径）给 u ≤ m−1。
> 本文用中心剩余，故取 α/2，比非中心口径更紧一倍。

**这个界与三样东西无关**（推导只用了 |r| ≤ a_i/2）：

| 无关项 | 含义 |
|---|---|
| 输出基 B | 误差量级只由**输入基的积 Â** 决定 → 这是「P ≥ max digit」的种子 |
| Â_i^{-1} 是不是逆元 | **正确性由逆元保证，误差界由约减保证——两条独立约束** |
| 输入 x 的取值 | 最坏情况分析不需要知道输入 |

### 2.4 求和式里哪些量跨 output tower 共享、哪些按列独立（validation 1）

把 BConv 看成 GEMM：M = k（输出 tower），K' = m（输入 tower），batch = N（系数）：

    ŷ[n][j] = Σ_i x[n][i] · QHatInv_i · QHatModp[i][j] (mod p_j)

- **跨 output tower 共享**（只算一次，j 循环外）：
  x_i = c[i]·QHatInv_i mod q_i —— 每个输入 tower 每系数一个标量乘法；
  以及 Barrett 约约前的 128-bit 部分和结构。
- **按列独立**（每个输出 tower 一套）：
  QHatModp[i][j]（权重）、p_j（输出模数）、Barrett mu_j = ⌊2^128/p_j⌋。

→ 计算复杂度账：共享量把每系数成本从 O(m·k) 次乘降到 m 次共享乘 + m·k 次乘累加；
这正是 FPGA 脉动阵列 3×5 的 K 维复用结构，也是 OC 策略「算全列再丢弃」浪费的定量来源。

**对账**：dcrtpoly-impl.h:1233-1254（CPU 主路径）——外层 ri（系数）、中层 i 算
xQHatInvModqi（共享量）、内层 j 做 Mul128 累加（列独立权重），收尾用 BarrettUint128ModUint64
按列的 mu[j] 归约。三层循环次序与上面完全一致。

## 3. ModUp：digit j 的目标基为什么是 (Q_l \ Q_j) ∪ P（validation 2）

### 3.1 目标基的推导

P4（apply key）的运算是：

    c̃_{0,1}[t] = Σ_j ĉ_j[t] · evk_j[t]  (逐 tower t ∈ Q_l ∪ P 基上的点积)

两个事实决定目标基：

1. **evk 存在 Q_l ∪ P 全基上**（keygen 时按全 Q 加密 P·s′）。tower-wise 点积要求
   ĉ_j 在【与 evk 相同的全基】上有值 → digit j 必须被扩展到 (Q_l \ Q_j) ∪ P，
   加上自己原有的 Q_j，拼起来才覆盖全部 l+K 个 tower。
   **只扩到 P 是不够的**：Q_l 里 Q_j 之外的 tower（其余 digit 的地盘）上 ĉ_j 没有值，
   P4 的点积在这些 tower 上缺项；而这些位置的值数学上不是 0——
   **digit j 承载的整数是 d_j = c1 mod Q_j（中心剩余下 |d_j| ≤ Q_j/2），不是 c1 本身**，
   这些 tower 上应有的值是 d_j mod q_i，恰由 BConv 给出（带 u·Q_j 误差）。

   > 这个区别不是措辞：**整个误差分析依赖 |d_j| ≤ Q_j/2**。
   > 若 digit 承载的是 c1（可达 Q_l），误差界就变成 u·Q_l，digit 分解将完全失去意义。
2. **为什么用近似值而不是精确 CRT lift**：精确 lift 需要对 Q_l 全基做带误差修正的精确
   基转换（SwitchCRTBasis 多一步 αQModp 修正项），而近似误差 u·Q_j 在 ModDown 除以 P 后
   变成 u·Q_j/P ≤ u（当 P ≥ Q_j），是可接受的小噪声。用 α·K 个标量换掉一次精确 lift，
   这就是 HKS 相对 GHS 的核心交换。

**形状**：digit j 的输出基 C_j = (Q_l \ Q_j) ∪ P，|C_j| = l − a_j + K
（a_j = digit j 实际 tower 数；最后一个 digit 残缺时 a_j < α，见 q5）。
注意输出基的 tower 顺序按 ComplPartQ 的构造序（先其余 Q tower 后 P tower），
不是 QlP 序——拼成 QlP 序是 assemble 步的事。

**对账**：rns-cryptoparameters.cpp:240-272——sizeComplPartQj = (l+1) − sizePartQj + sizeP；
前 (l+1)−sizePartQj 个模数取「currDigit >= j 时自增跳过自己」的其余 digit 的 tower，
后 sizeP 个取 moduliP。与推导的 C_j 逐元素一致。

### 3.2 ModUp 各步数据形状（自画形状链，P1-P5 + 拼装）

记 N×t = t 个 tower、每 tower N 个系数。当前参数 l=3, α=2, K=2, dnum=2, a_0=2, a_1=1。

```
输入 c1（EVAL）:                     2 × (N×l) 中取 c1        →  N×3
│
│ P1a digit 分解（tower 切片，零填充，无加权）
│     keyswitch-hybrid.cpp:353-380
```

    (N×l) → dnum×(N×α) → dnum×(N×(l+K−α)) → dnum×(N×(l+K)) → 2×(N×(l+K)) → 2×(N×l)

（中间 2×(N×(l+K)) 是 P4 输出；task.yaml 写的链把 digit 拼装与 P4 合并记了一步。）

**每个算子的 NTT 域要求**（决定 INTT/NTT 调用数，L1 算子账的根）：
- BConv：输入输出都在 COEFF（求和式是系数逐位的）；
- P4 点积：EVAL（点积即 NTT 域乘法）；
- 因此 ModUp 每 digit 必有 INTT(α) + NTT(l+K−α) 一组往返；
  其中 Q_j 段的 EVAL 版本在 assemble 时可直接复用 c1 原值（DC 分支 :473-478 还是
  多做了一次 NTT——这是 gap 分析里可抠的点）。

## 4. ModDown：推导 + 为什么不需要 digit 分解（题 3）

> 符号以 [L0_符号表.md](L0_符号表.md) 为准。注意 `ρ = c̃ mod P`（初稿误记为 `s`，与密钥撞车），
> 「想要的结果」记 `g`（初稿用 `m`，与通用 BConv 的输入基素数个数撞车）。

### 4.0 ModDown 要解决什么（动机）

```
输入：c̃ 在基 Q_ℓ ∪ P 上         ℓ + K 个 tower
输出：out = round(c̃/P) 在 Q_ℓ 上   ℓ 个 tower
```

形状缩减 + 数值除以 `P`。**除以 P 是为了把 KS 噪声压小 P 倍**（题 1 九步链第 ③ 步）。

#### 为什么不能直接乘 P^{-1} mod q_i

`P` 与每个 `q_i` 互素，`P^{-1} mod q_i` 存在。那为什么不能一行搞定？

    把 c̃ 写成 c̃ = P·g + η          g = 想要的，η = KS 噪声（小）

    (c̃ · P^{-1}) mod q_i = g + η · P^{-1}  mod q_i
                               └─────┬─────┘
                    P^{-1} mod q_i 是个 ~2^60 的任意数
                    小整数 × 大数 → 结果在 [0,q_i) 里乱跑

**信号 `g` 是对的，问题纯粹在噪声没缩小。**（又一次「正确性与噪声是两条独立的线」）

> ### 要提炼的一句话
> **模运算里的「除法」不是除法，只是乘一个数——它对整数意义上的大小没有任何缩小作用。
> 要真的把噪声变小，必须在【整数域】里做除法。**

#### 整数域除法的前提

整数除法要求被除数**真能整除**。所以先减掉余数：

    ρ = c̃ mod P（中心剩余，‖ρ‖ ≤ P/2）
    带余除法：c̃ = k·P + ρ    ⟹    c̃ − ρ = k·P        ← 显然是 P 的倍数

**减掉余数，剩下的就是「商 × P」。而商 `k` 正是我们要的 out。** 这是小学除法，
没有任何 RNS 特有的东西——但它逼出了 ModDown 的全部步骤。

### 4.1 算法：从「必须凑成 P 的倍数」倒推

对应 `ApproxModDown`（dcrtpoly-impl.h:1315-1354）。

#### 缺什么

目标是对每个 `i ∈ [0,ℓ)` 算出

    out_i = [ (c̃ mod q_i) − (ρ mod q_i) ] · (P^{-1} mod q_i)  mod q_i
              └─────┬─────┘   └────┬────┘     └───────┬──────┘
                有 ✓           没有 ✗            有 ✓（host 预计算）

**三个量里只缺一个：`ρ mod q_i`。**

#### `ρ` 的 P 侧残数是零成本的

    ρ = c̃ mod P，  p_j | P   ⟹   ρ ≡ c̃ (mod p_j)   ⟹   ρ mod p_j = c̃ mod p_j

> **`c̃` 的 P 侧那 K 个 tower，同时就是 `ρ` 的 P 侧残数。同一批数据，两个身份，不需要任何计算。**

#### 于是问题自动成形为 BConv

    已知：ρ 在基 {p_1,…,p_K} 上的 K 个残数
    求：  ρ 在基 {q_1,…,q_ℓ} 上的 ℓ 个残数

**与 §2 的问题设定一字不差**，只是换了基。代价是近似误差 `w`，`‖w‖ ≤ K/2`（§2.3，`m = K`）。

#### 四步（现在每一步都是「必然如此」）

    1. 取 c̃ 的 P 侧 K 个 tower，INTT            ← BConv 要在系数域
    2. BConv：基 P → 基 Q_ℓ，得 ρ̂ = ρ + w·P     ← 唯一能跨基的工具
    3. NTT 回 EVAL                              ← 后面要与 Q 侧逐 tower 相减
    4. out_i = (c̃_i − ρ̂_i) · (P^{-1} mod q_i) mod q_i

#### 第 4 步凭什么是「除法」

**执行的是模乘，达成的是整数除法。**

    被乘数 A = c̃ − ρ̂ = (c̃ − ρ) − w·P = P·M      两项都是 P 的倍数 ⟹ A = P·M

    A · (P^{-1} mod q_i) mod q_i = (P·M)·P^{-1} mod q_i = M mod q_i     ← 真商的残数

> **乘 `P^{-1} mod q_i` 这个动作永远只是一次模乘。它算的是不是除法，
> 完全取决于被乘数是不是 `P` 的整数倍：是 → 拿到真商；不是 → 拿到垃圾。**
>
> **前面那一串（INTT → BConv → NTT → 相减）存在的唯一目的，就是把被乘数凑成 `P` 的整数倍。**

数值验证见附录 A.2（`c̃=59, P=7, Q_ℓ=15`：两次模乘算出 `56÷7=8`，全程不构造大整数）。

#### 结果（修正初稿）

    out = round(c̃/P) − w = g + η/P − ρ/P − w

初稿写的是 `out ≡ c̃/P + w`，两处不准：符号、以及 `c̃/P` 应为 `round(c̃/P)`。
**而且那个 round 不是近似，是精确的**——中心剩余下减掉 `c̃ mod P` 恰好实现最近整数舍入。
初稿 §4.1 第 5 步把 round 说成「被吸进近似」，删。

### 4.2 `ρ` 的真实作用：让除法合法，不是消噪声

**这是本轮最大的认知修正。**

    除以 P   →   噪声 ÷ P          ← 消噪声的是【这个】
    减掉 ρ   →   让除法在整数域合法  ← 而且自己【带来】ρ/P 的舍入残差

#### 三个证据

**① `ρ` 根本不知道噪声是什么。**
`ρ = c̃ mod P` 只用 `c̃` 算出，**不需要密钥 `s`**；而 `η` 只在解密组合 `c̃_0 + c̃_1·s` 里存在，
**必须有 `s` 才能定义**。一个不需要 `s` 的量，不可能减掉一个只有知道 `s` 才存在的东西。

**② 噪声账里 `η/P` 没有消失。** 见 §4.4 的四项表——`η/P` 还在，只是变小了。
如果减 `ρ` 能消噪声，它应该不见了。

**③ 思想实验。**

    令 P = 1：ρ = c̃ mod 1 = 0，减了等于没减；除以 1 等于没除；噪声 η/1 = η 纹丝不动。
             → 减 ρ 照做了，噪声没变 ⟹ 消噪声的不是它。

    假装能直接除：c̃/P = g + η/P，噪声照样小 P 倍。
             → 根本没减 ρ，噪声照样小 ⟹ 除法一个人就够了。

> **`减 ρ` 是手续费，不是收益来源。**

#### 噪声为什么会变小

不是"减掉了噪声"，是**整个数除以 P**：信号 `P·g` 里的 `P` 被除掉后还原成 `g`（不变），
噪声 `η` 却真的小了 `P` 倍。**这就是「抬高模数再降回来」的全部原理。**

### 4.3 为什么 ModDown 不需要 digit 分解（validation 3）

四层理由，**第 0 条是机制层，最本质；后三条是结果层的佐证**：

0. **根本不存在可被分解解决的机制**。ModUp 分解的动机是它后面接着**乘 evk**：
   噪声 = |digit|·|ε| / P，**正比于 digit 大小**，所以把 digit 切小噪声就小。
   而 ModDown 后面**没有乘 evk**——它只是基变换 + 除法，不存在任何
   「噪声 ∝ 输入大小」的放大机制。
   **不是「分解了收益不大」，是「没有那个可被分解解决的问题」。**

1. **基的大小方向相反**。BConv 的误差是输入基的积的倍数。ModDown 的输入基是 P
   （K 个素数，K 很小），输出基是 Q_l（大）。从【小基】转到【大基】，误差 = K·P，
   除以 P 后只剩 O(K)。digit 分解的作用是把【大】输入基切小以压误差——这里输入基
   已经天然很小，没有可切的东西。
2. **P 本身就是一个不可再分（也不需要再分）的辅助基**。P 的 K 个素数就是「digit」
   的全部；再分只会让误差项从 K·P 变成 Σ(子基积)，而任何划分的子基积之和 ≥ K·P^{...}
   不会更优，反而增加 BConv 次数。
3. **误差预算已经够**。ModDown 噪声 O(K)（每系数 ~2·2^0）远小于 ModUp 带进来的
   α·Q_j/P ≈ O(α) 噪声和密文本底噪声，不是瓶颈，不值得为它加复杂度。

**对账**：ApproxModDown 里对 partP 只调一次 ApproxSwitchCRTBasis（P→Q 方向，
PHatInvModp / PHatModq 预计算，rns-cryptoparameters.cpp:203-216），全程无
numPartQ 概念。

### 4.4 全链路噪声账（改写初稿 4.3）

> 初稿把噪声估成 `‖Σ_j u_j·Q_j·evk_j/P‖ ≈ β·‖c1‖·Q_j/P`，
> 把 `evk_j` 当整体估了量级（≈ `Q_ℓ·P` 尺度）——**高估了**。
> 真正存活的只是 `u_j·Q_j·ε_j`（`ε_j` 是小量）。下面是修正版。

#### 噪声的唯一源头是 evk 的 `ε`

    evk_j 满足：b_j + a_j·s = P·s′·E_j + ε_j       ‖ε_j‖ ≤ B（几比特）

`ε` 来自 **RLWE 的安全性要求**——不带误差的 LWE 可直接解出。**这是唯一的源头。**

#### BConv 不【产生】噪声，只【放大】噪声

    ĉ_j = d_j + u_j·Q_j                     ← BConv 让它多了 u_j·Q_j

    η = Σ_j ĉ_j·ε_j
      = Σ_j d_j·ε_j   +   Σ_j u_j·Q_j·ε_j
        └────┬────┘       └──────┬──────┘
        本来就有的          BConv 贡献的

**两项都带 `ε_j`。**

> ### 若 evk 无误差（`ε_j = 0`），BConv 的误差 `u·Q_j` 一点噪声都不产生。
> ### BConv 不生产噪声，它只是给 `ε` 配了个更大的乘数。

放大倍数：

    ‖d_j‖ ≤ Q_j/2 ，  ‖u_j·Q_j‖ ≤ (α/2)·Q_j      ⟹   η 被放大约 (1+α) 倍

**这就是 `P ≳ α·Q_j` 里那个 `α` 的准确出处。**

信号项不受影响：主项里 `u_j·Q_j` 被 `E_j` 归零（`Q_j` 与 `E_j` 各在互补的 tower 集上为 0）
——**BConv 误差只污染噪声，不污染信号**。

#### 四项噪声（ModDown 之后）

    out_0 + out_1·s = g + η/P − (ρ_0 + ρ_1·s)/P − (w_0 + w_1·s)
                          └┬┘   └───────┬──────┘   └─────┬─────┘
                           ①             ②                ③

| # | 来源 | 谁引入 | 性质 | 量级 |
|---|---|---|---|---|
| ① | evk 的 `ε`，经 ÷P | RLWE 安全性 | **唯一源头** | `dnum·(1+α)·Q_j·B / (2P)` |
| ②' | ModUp BConv 的 `u·Q_j` | BConv | **放大 ①，约 (1+α) 倍**，不是新项 | 含在 ① 里 |
| ② | ModDown 舍入 `ρ/P` | 减 `ρ` 的手续费 | 新增 | `< ‖s‖/2` |
| ③ | ModDown BConv 的 `w` | BConv | 新增 | `≤ K‖s‖/2` |

> **② ③ 为什么带 `‖s‖`**：ModDown 对 `c̃_0`、`c̃_1` **分别**做，两次舍入残差不抵消，
> 而解密时 `out_1` 要乘密钥 `s`。这是 ModDown 的固有代价。

#### 于是 P 的约束闭合

    P ≳ α · Q_j · B        ← 让 ① 掉到与 ②③ 同量级（个位数）

再大就是浪费模数预算。用比特看：`log₂(小因子) ≈ 4~8 bit < 单个素数 50~60 bit`
⟹ **限位计数上 `K = α`，最多 `+1`**。

**对账**：`rns-cryptoparameters.cpp:129-136` — `maxBits` = 最大 digit 的位宽，
`sizeP = ⌈maxBits/auxBits⌉`。**K 由 α 和位宽推出，不是自由参数。**
CiFlow 表 III 五组 `K=α` 命中 4/5；HERA 表 3 `α=8, K=9` 即 `K=α+1`，
多出的那个 50-bit 素数装的正是上面那几比特余量。

### 4.5 方法论：整数层面 vs 残数层面

本轮的三个困惑其实是**同一个来源**——一直在残数层面找答案：

| 问题 | 残数层面（看不到） | 整数层面（答案在这） |
|---|---|---|
| 「取模后不就没了吗」 | 只有残数 | 残数唯一确定一个整数，它一直在 |
| 「MD 里没有除法啊」 | 只有模乘 | 模乘 = 整数除法（当整除成立时） |
| 「噪声呢，怎么看不见」 | 看不见 | 噪声藏在需要密钥才能展开的解密组合里；`η → η/P` |

> ### 通用模式
> **写代码时在【残数】层面操作；想问题时在【整数】层面思考。**
> **两者由环同构对应——残数上做对了运算，整数上就自动得到对应的结果。**
>
> 设计 RNS 算法时永远先在整数层面想清楚"我要对那个看不见的整数做什么"，
> 再落到残数层面找"哪串模运算能实现它"。倒过来一定卡住。

**对账**：rns-cryptoparameters.cpp:129-136——maxBits = 单个 q 的最大位宽（注：实现取的是
素数位宽，故 P ≈ 2^{K·auxBits} ≥ 2^{α·qbits} 的满足由 dnum 划分保证，即每个 digit 的
总位宽 ≤ K·auxBits），sizeP = ⌈maxBits/auxBits⌉。K 由 α 和位宽推出，**不是自由参数**。
（严格说代码里 maxBits 是单素数位宽，digit 总位宽 α·qbits 的约束落在
numPartQ/α 的选取上：选 α 使得 α·qbits ≤ K·auxBits 成立——两条约束联立才闭合
P ≥ max digit。此处与代码完全一致，推导无矛盾。）

## 5. 三条 validation 汇总（自检清单）

1. **BConv 求和式**（§2.2）：ŷ_j = Σ_i x_i·QHatInv_i·QHatModp[i][j] mod p_j。
   共享量：x_i = c[i]·QHatInv_i（j 循环外算一次）；列独立：QHatModp[i][j]、p_j、
   Barrett mu_j。对账 dcrtpoly-impl.h:1233-1254 ✓
2. **目标基**（§3.1）：(Q_l \ Q_j) ∪ P，因为 P4 逐 tower 点积要求 ĉ_j 与 evk 同在
   Q_l∪P 全基上有值；只扩 P 则 Q 侧其余 tower 缺项。近似代替精确 lift 的代价
   u·Q_j 由 ModDown 消化。对账 rns-cryptoparameters.cpp:240-272 ✓
3. **P ≥ max digit**（§4.4）：噪声唯一源头是 evk 的 ε；**BConv 不产生噪声，只把它放大 (1+α) 倍**
   （ε=0 时 BConv 误差贡献为 0）；ModDown 除以 P 后残差降到 O(α·B)。
   K = sizeP 由 ceil(maxBits/auxBits) 定死，非自由参数。对账 rns-cryptoparameters.cpp:129-136 ✓

**附加结论（题 3 深化）**：
4. **`ρ` 的作用是让除法合法，不是消噪声**（§4.2）——消噪声的是 ÷P，减 ρ 反而带来舍入残差。
5. **模乘 = 除法的条件**（§4.1）：`×P⁻¹ mod q_i` 永远只是模乘；它是否等价于除法，
   只取决于被乘数是不是 P 的整数倍。ModDown 前面那一串的唯一目的就是凑出这个整除性。

### A.1 CRT 重建与约减（题 1）

```
q_0 = 3,  q_1 = 5,  Q = 15,  α = 2
```

**造基向量**：

| | Q̂_i = Q/q_i | Q̂_i⁻¹ mod q_i | E_i = Q̂_i⁻¹·Q̂_i | 验证 |
|---|---|---|---|---|
| i=0 | 5 | 5⁻¹ mod 3 = 2⁻¹ mod 3 = **2** | 2×5 = **10** | 10 mod 3 = 1 ✓，10 mod 5 = 0 ✓ |
| i=1 | 3 | 3⁻¹ mod 5 = **2** | 2×3 = **6** | 6 mod 3 = 0 ✓，6 mod 5 = 1 ✓ |

**重建 a = 7**（`a_0=1, a_1=2`）：

```
X = 1×10 + 2×6 = 22          ← 求和式，不 mod Q
a = 22 mod 15 = 7  ✓
u = (22 − 7)/15 = 1 = α − 1  ✓ 界是紧的
```

**关键**：`X = 22 ≠ a = 7`，差了 `u·Q = 15`。**这两个数不是一回事**（§0 踩坑 ①）。

**约减的效果（取 a = 11，`a_0=2, a_1=1`）**：

```
第 0 项：a_0·c_0 = 2×2 = 4 ≥ q_0=3，需约减
    不约减：  4 × 5 = 20
    约减：  (4 mod 3) × 5 = 5
    差 15 = Q ✓ mod Q 后相同

第 1 项：a_1·c_1 = 1×2 = 2 < 5，两者相同 = 6

X_不约减 = 26 → mod 15 = 11 ✓        X_约减 = 11 → mod 15 = 11 ✓
```

### A.2 ModDown：两次模乘算出一次除法（题 3）

```
Q_ℓ = 15 (q_1=3, q_2=5)    P = 7    c̃ 活在 mod 105
```

设那个**看不见的整数** `c̃ = 59`，目标 `out = round(59/7) = 8`。

**手上只有三个残数**：

```
c̃ mod 3 = 2      c̃ mod 5 = 4      c̃ mod 7 = 3
└──── Q 侧 ────┘                  └─ P 侧 ─┘
```

| 步 | 操作 | 结果 |
|---|---|---|
| 1 | `ρ` 的 P 侧残数 = `c̃` 的 P 侧残数 | `ρ mod 7 = 3` **（零成本）** |
| 2 | BConv `{7} → {3,5}` | `ρ mod 3 = 0`，`ρ mod 5 = 3`（单素数输入基，恰好精确，`w=0`） |
| 3 | 逐 tower 相减 | mod 3：`2−0 = 2`；mod 5：`4−3 = 1` |
| 4 | 乘 `P⁻¹` | `7⁻¹ mod 3 = 1` → `2×1 = 2`；`7⁻¹ mod 5 = 3` → `1×3 = 3` |

**核对**：结果 `(2,3)` 在基 `(3,5)` 上 → CRT → `8`。而 `8 mod 3 = 2 ✓`，`8 mod 5 = 3 ✓`。

```
全程没有出现过 59，没有出现过 56，也没做过一次真的除法。
第 3 步的两个减法代表的整数是 59 − 3 = 56 = 7 × 8 —— 整除性是【减法自动带来的性质】，
不是任何"凑"的操作。
第 4 步两次模乘，算出的正是 56 ÷ 7 = 8。
```

**这个例子同时验证了 §4.5 的方法论**：残数层只有加减乘，整数层发生了除法。
