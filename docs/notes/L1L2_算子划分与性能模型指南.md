## 0. 目标与原则

**目标**：从 CKKS Hybrid Key-Switching 的数学公式出发，推导出算子 DAG 与调度设计空间（L1），再用三个性能模型（L2）预测 DC/MP/OC 三策略在任意参数点的延迟与缓冲，最终支撑 Portfolio R1（策略选择相图）与 R2（批深度耦合）两个研究假设。

**三条原则**：

1. **自上而下**：先定需求和约束，再做设计。"设计是在给定需求和约束下逻辑推理的结果；需求或约束变化，就会带来设计变化。"——每一个模型参数都必须能回答"它由哪一层的需求决定"。
2. **模型先于修复**：修 OC（CP-005）之前先完成本指南的模型 v0，否则修完的数字无法被解释（对应 Portfolio F2/F3 先行的顺序）。
3. **每一项可校准**：模型中每个系数必须对应一个可复现的实测点（F2 口径），禁止拍脑袋常数。

## Part A：L1 算子划分推导

> **术语统一（2026-08-03）**：全文统一用 **limb**：指单个模数 q_i / p_j 下的一个多项式，
> 含 N 个 64-bit 系数，单 limb 字节数 tower_bytes = N×8B（N=4096 时 32KB）。
> tower 为同义词，后续文档不再混用。


### A1. 前置：L0 公式链自查表

开始 L1 推导前，先确认 L0 五步能自己推出来（不翻论文）：

| Step | 内容 | 对应 OpenFHE 代码 |
|------|------|------------------|
| 1 | digit 分解：c1 按 tower 切成 dnum 个**不相交** digit（无 P_i 加权）；P 加权嵌入 evk（第 j 份 evk 仅在自己的 α 个 tower 上加密 P·s′） | keyswitch-hybrid.cpp:353-380（分解）、:126（evk 构造 `PModq[i]*sOldi`） |
| 2 | ModUp/BConv（近似基扩展，P2）：每 digit α→β 个 tower，ĉ[q] = Σ (c[q′]·Q̂⁻¹ mod q′)·Q̂ mod q | `ApproxSwitchCRTBasis`（dcrtpoly-impl.h） |
| 3 | P3 NTT 全部 ĉ，与 digit 原 tower 拼接为 partsCtExt（dnum × N × (ℓ+K)） | keyswitch-hybrid.cpp:471-499（assemble） |
| 4 | P4 Apply Key：cTilda_{0,1} = Σ_j Σ_i ĉext_j[i]·(b,a)_{j,i}，逐 tower 点积 MAC | `EvalFastKeySwitchCoreExt`（:634-657） |
| 5 | ModDown：(cTilda_Q − BConv(cTilda_P, P→Q))·P⁻¹ mod Q，每 poly 各一次 | `ApproxModDown`（dcrtpoly-impl.h:1315） |

> 修正记录（2026-08-03）：初稿 Step 1 写的是 Han-Ki 原文的带权分解 c1 = Σ c1^(i)·P_i；
> 但 OpenFHE（eprint 2021/204 附录变体）实际是 tower 不相交切分 + P 加权嵌入 evk，
> 已按 keyswitch-hybrid.cpp 代码事实修正。

**关键数学性质（L1 的全部切分依据）**：① ModUp 中各 output tower 的求和相互独立（"j 之间零依赖"，见 gap 分析 §5.1）——允许 BConv 粒度从 full-sizeP 切到 single-tower；② digit j 自己的 α 个 tower 在 partsCtExt 中**原样直通**（不过 BConv，只在 COEFF→EVAL 往返）——这是 Section1 bypass 的算法根源。

**验收**：能徒手写出 Step 2 的求和式并指出哪些量对所有 tower 共享（xQHatInvModqi）、哪些按列独立（QHatModp[i][j]、Barrett 常数）。

### A2. 循环嵌套形式化

HKS 全部工作负载是这一个四层循环嵌套：

```
for d in [0, dnum):                # digit 维（dnum = numPartQl）
  for p in [0, sizeQl + sizeP):    # output tower 维（Section1: p<sizeQl, Section2: p≥sizeQl）
    for n in [0, N):               # ring 元素维（FPGA 内被 PE_PARALLEL 并行吃掉）
      op ∈ {INTT, BConv, NTT, MAC} # 算子选择与融合维
```

当前玩具参数：N=4096, sizeQl=3, sizeP=2, alpha=2, dnum=2。

### A3. 设计空间的三个自由度

| 自由度 | 取值空间 | 影响 |
|--------|---------|------|
| **F1 循环序** | digit-major / tower-major / 屏障分段 | 峰值缓冲、数据复用距离 |
| **F2 算子粒度** | full-sizeP BConv / single-tower BConv | 计算量、D2H 流量、PE 利用率 |
| **F3 融合决策** | INTT 复用（是/否）、Section1 bypass（是/否）、累加位置（host / on-chip） | 调用次数、PCIe 流量 |

### A4. 已知调度点（用代码锚定，禁止凭记忆）

| 策略 | F1 循环序 | F2 粒度 | F3 融合 | 代码锚点 |
|------|----------|---------|---------|---------|
| **DC** | digit 外层，INTT→BConv→NTT 逐 digit 交织 | full-sizeP | 无 bypass | keyswitch-hybrid.cpp:427-458 |
| **MP** | 三段全局屏障：全 INTT → 全 BConv → 全 NTT | full-sizeP | INTT 集中复用 | :405-465 |
| **OC**（真，CiFlow 目标态） | tower 外层 | single-tower | INTT 复用 + Section1 bypass + on-chip 累加 | :501-587（当前为伪 OC，修复路径见 task.yaml） |

注意 `peak_p_towers` 字段：DC=sizeP、MP=dnum×sizeP、OC=1——这是循环序的**直接推论**，不是独立测量量。模型里峰值缓冲必须由循环序推出，再用 MemoryTracker 实测校验。

### A5. 推导步骤与输出物

1. 对三策略分别写出调度伪代码（gap 分析 §3 已有 OC vs 伪 OC 版本，补 DC/MP）。
2. 从伪代码**数出来**（不是查表）每策略的：BConv 次数、NTT/INTT 次数、H2D/D2H 字节数、峰值缓冲、offload 调用次数。对照 OC gap 分析 §4 的算术表验证方法。
3. **设计空间扫描**：3 自由度共可组合出约 12 个点，当前只占 3 个。列出未占点并各写一句"为什么没人做 / 值不值得做"。重点关注：tower-major + full-sizeP（介于 MP 与 OC 之间）、batch 维展开（R2）。这是论文 idea 的来源："其他人工作没考虑到的需求和约束，idea 自然出现"。

**输出物**：设计空间表（自由度 × 取值 × 已占点标注 × 未占点一句话评价），存入 `docs/papers/` 作为论文 §5 的推导素材。

## Part B：L2 三性能模型

总公式（F3 的骨架，三模型各占一项）：

```
T_strategy(N, L, dnum) = Σ_op n_op(策略)·c_op(N)     ← 计算模型
                       + V(策略) / BW_eff             ← 存储模型
                       + n_offload(策略)·T_fixed      ← 控制模型（本系统区别于 CiFlow 的关键项）
```

其中 `n_op`、`V`、`n_offload` 全部由 Part A 的循环序/粒度/融合决策推出——这就是 L1→L2 的推导链。系数 `c_op`、`BW_eff`、`T_fixed` 用实测校准。

### B1. 计算模型（算子单价表）

**方法**：每个算子建一张单价卡，区分 csynth 估算与上板实测两个口径（F2 对账前两套都记录）。

| 算子 | csynth 口径 | 上板口径（表 5-4 实测，N=4096） | 备注 |
|------|------------|------------------------------|------|
| NTT / limb | 15,701 cyc（7.17× vs 变几何） | DC 中 NTT 合计 2512μs / 4 poly，折算单 limb 单价 | CG-NTT，PE_PARALLEL 当前=4 |
| INTT / limb | 同上×修正系数 | DC INTT 789μs / 2 次调用 | 上板 3.08× 加速 |
| BConv（full-sizeP=2） | ~8,232 cyc/limb 组 | DC BConv 938μs / 2 次；OC 2656μs / 4 次 | 上板 2.88× 加速 |
| BConv（single-tower） | ~3,600 cyc（gap 分析 §5.2） | 待测（OC 修复后补，CP-005 验收项） | PE 利用率掉到 20%，单价≠full/5 |

**校准规则**：单价必须按 `(N, sizeQl, sizeP)` 参数化记录；每新增一个实测点（F4 勘察点），回填本表并在 log.md 记录。
**推导练习**：用本表独立算出 DC 的 Precompute 总延迟预测值，与实测 4470μs 对账，误差 >15% 时必须找到缺失项（通常是控制模型项）而不是调系数。

### B2. 存储模型（带宽 + 缓冲）

**三个子模型**：

1. **流量模型**：`V(策略) = Σ_call bytes_per_call`，bytes 由 Part A 数出。已知锚点：BConv 单次 H2D = sizeQ×N×8B（96KB @ sizeQ=3），D2H = sizeP×N×8B（full）或 N×8B（single-tower，5× 缩减，gap 分析 §5.2）。
2. **带宽模型**：`BW_eff = 实测数据量 / (总传输时间 − n_call·T_fixed_dma)`——注意必须先扣掉每次 DMA 的固定延迟再折算带宽，否则得到的是被固定开销污染的 787 MB/s 假带宽。PCIe 合计占端到端 32.7%（表 5-4）是存储模型的主导证据。
3. **缓冲模型**：`peak_buf(策略) = peak_p_towers(循环序推论) × tower_bytes + 输入常驻`。实测锚点：DC 64KB / MP 128KB / OC 32KB（表 5-4）。**验收**：三个值必须能从 A4 的 `peak_p_towers` 纯推出来，推不出来说明缓冲模型漏了项。

**R2 接口**：批深度公式 `depth = floor(B_onchip / peak_buf(策略))`（ADR-005）直接消费缓冲模型输出——OC 32KB vs MP 128KB → 4× 深度，这是 R2 假设的定量入口。

### B3. 控制模型（本项目的独占贡献区）

**两个开销源**：

1. **offload 固定开销** `T_fixed`：单次 kernel launch + buffer sync + XRT 调度的不可摊销部分。锚点：端到端 182.8μs 中 H2D 22.2% / kernel 67.3% / D2H 10.5%，DMA 固定延迟 ~20-30μs/call（实验规划 §补5-1 分析）。校准方法：同一策略下对 batch=1 与 batch=2 的端到端延迟做差，差值≈计算增量，公共部分即 T_fixed。
2. **opcode 派发开销**：ADR-008 已论证开销比 <1%（NTT ~300K cyc 级计算 vs μs 级 RPC），模型中记为可忽略项，但**必须写明忽略依据**，这是控制模型完备性的一部分。

**策略敏感度**（控制模型解释"为什么 DC 赢"的核心）：

| 策略 | kernel 调用次数（表 5-4） | 控制项 = n×T_fixed 排序 |
|------|--------------------------|------------------------|
| DC | 45 | 基准 |
| MP | 45 | ≈基准 |
| OC（伪） | 44 但 BConv 粒度变细 → 修复成真 OC 后 single-tower 调用数 ×sizeP，控制项上升 | OC 细粒度化的固定开销惩罚即来自本项 |

**R1 接口**：相图纵轴"固定开销/带宽比"就是 `T_fixed / (N·8B / BW_eff)`，横轴参数规模 `N·L·dnum`——两轴分别由控制模型与存储模型供给。

### B4. 模型校准与验证协议

1. **校准点**：(N=4096, sizeQl=3, sizeP=2, dnum=2) 三策略实测（表 5-4）。
2. **验证判据**（沿用 Portfolio R1）：真 OC 修复后实测落在模型预测 ±15% 内；模型对至少两个非校准点（F4 新参数点或 batch=2/4）做出正确胜者预测。
3. **回归保护**：模型预测表随每个新实测点更新，写入 log.md；若实测偏离预测 >15%，先查是否漏项（禁止调系数凑数）。

## Part E：反模式（不要做的事）

1. **先修 OC 再建模**——修完的数字没有模型解释，等于又一次孤立约束响应。
2. **用 csynth 周期数直接预测端到端延迟**——漏掉 PCIe/固定开销项，在本系统误差可达 30%+。
3. **把 787MB/s 当 PCIe 带宽写进模型**——那是被 DMA 固定开销污染的折算值。
4. **调系数凑实测**——偏离 >15% 说明模型漏项，回 Part A 检查循环序是否数错。
5. **凭记忆引用策略行为**——一切以 keyswitch-hybrid.cpp 当前代码为准（OC 目前是伪实现）。
