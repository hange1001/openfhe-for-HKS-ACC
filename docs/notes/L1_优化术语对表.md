## 1. 主表

### 1.1 并行性（导师条目：数据并行 / 任务并行 / 流水线并行）

| 通用术语 | 一句话定义 | 本项目的实例 | 证据锚点 | 状态 |
|---|---|---|---|---|
| **数据并行**<br>(data parallelism) | 同一操作作用于无依赖的多份数据 | `n` 维：`N=4096` 个系数在 BConv 内**零依赖**；`j` 维（输出 limb）之间也零依赖。二者合起来 = GEMM 的 batch 维与 M 维 | L1L2 §2.1 的 GEMM 三元组 `(K=α_d, M=\|C_d\|, batch=N)`；task.yaml 1.3 `derived_mechanism` | ✅ |
| **任务并行**<br>(task parallelism) | 不同的操作同时执行 | `dnum` 个 digit 的 ModUp 相互独立——各自的 BConv 目标基不同、乘的 `evk_j` 不同，**只在 P4 之后才汇合累加** | L0闭卷 §3.1；符号表 §3；L1L2 §2.5 点 6 | 🟡 从未作为一个**并行维度**记账，只当作循环边界 |
| **流水线并行**<br>(pipeline parallelism) | 不同阶段在时间上重叠 | 两个层次：<br>① 算子级 `INTT → BConv → NTT` 三段<br>② HLS 级 `load / compute / store` 三段 | task.yaml phase4 步 4.1（117K→87K cycles）、4.2 | ❌ 只有 TODO 和一个未解释的目标数字，没进任何模型 |

> **注**：三种并行在本项目是**同一个循环嵌套的不同维度**，不是三种技术。
> 六层循环 `d(digit) / i(输入 limb) / j(输出 limb) / n(系数)` 中：
> `d` → 任务并行；`j, n` → 数据并行；`i` → 归约维（不可并行，只能树形化）；
> 流水线并行是**跨算子**的，不在这个嵌套里，它在 `INTT/BConv/NTT` 的串联上。

## 3. 三个空白的展开

### 3.1 延迟 vs 吞吐率 —— 最重要的一个

**症状**：L2 模型写成加法

```
T = Σ n_op·c_op  +  V/BW_eff  +  n_call·T_fixed
    └ 计算 ┘        └ 传输 ┘      └ 控制 ┘
```

**加号 = 假设三项完全不重叠。** 这个假设从未被声明过，更没被验证过。

**更值得警惕的一点**：L1L2 §4 已经查实，CPU 路径的「总延迟」是**记账加总**而非独立计时
（`789+938+2512+231 = 4470` 精确闭合）。而 FPGA 路径的 8,229 μs 同样是
`H2D 1829 + kernel 5537 + D2H 863` 的精确加总——**同一个方法论问题，在另一条路径上重演，但没被点名。**
如果 XRT 的 H2D 与 kernel 实际有重叠，那么 8.229 ms 是一个**上界**，不是墙钟时间。

**要答的三个问题（按顺序）**：

1. `FpgaManager` 的 offload 是阻塞的吗？查 `enqueueTask` / `enqueueMigrateMemObjects` 之后有没有立刻 `finish()`/`wait()`。
   - 若是阻塞的 → 加号成立，但那是**一个可消除的架构缺陷**（ADR-008 的推论），不是物理定律。
   - 若非阻塞 → 现有全部延迟数字口径存疑，需要重测。
2. 把模型写出两个版本，都算一遍：
   ```
   串行版：T = T_comp + T_mem + T_ctrl                    ← 现状
   重叠版：T ≈ max(T_comp, T_mem) + ramp_up + drain + T_ctrl_不可重叠
   ```
   两版对 DC 的差值 = **「把 offload 改成异步/双缓冲」的收益上界**。这是一个 phase3 候选项，
   而且它可能**不需要动 HLS**（纯 host 侧改动，比 3.1 修 OC 还便宜）。
3. `T_fixed` 里哪部分能被隐藏？`T_f,H2D ≈ 30 μs` 若能与前一次 kernel 重叠，`n_call × T_fixed = 570 μs`
   这一项（占 DC 的 21%）大部分会消失。

**影响**：task.yaml step 1.4 的 `model_form` 需要增加重叠分支；step 1.2 实验 A 的计时方法需要
明确区分「分项加总」与「区间墙钟」（rationale 里已经警告过一次，但只针对 CPU 路径）。

### 3.2 负载均衡

**症状**：`α₀=2, α₁=1 → \|C₀\|=3, \|C₁\|=4` 这件事出现过三次（符号表 §3、L1L2 §2.3、task.yaml q5），
每次都被描述为「小参数产物，参数上推时选能整除的组合」——**这是一个规避建议，不是一个量化结论**。

**要答的问题**：

1. 若 `dnum` 个 digit **并行**处理（任务并行，见 §1.1），完成时间由最慢的 digit 决定：
   `T_parallel ∝ max_d(α_d + \|C_d\|)` 而非 `avg`。当前 `max = 5`，`avg = 5`——
   **等一下，`α_d + \|C_d\| = ℓ + K = 5` 对所有 `d` 恒成立**（符号表 §3）。
   那么不均衡到底出现在哪一步？→ **这是本节要先厘清的第一件事**：
   逐算子看，INTT 的工作量 ∝ `α_d`（2 vs 1，比 2:1），BConv 输出 ∝ `\|C_d\|`（3 vs 4，比 3:4），
   NTT 的工作量 ∝ `\|C_d\|`。总和相等，但**分算子看是不均衡的**——
   于是它在「每算子一次 offload」的 B0 边界下不构成问题，在 B1（每 digit 一次）下才构成问题。
2. 写出不均衡度的符号式：`imbalance(ℓ, dnum) = max_d W_d / avg_d W_d`，其中 `W_d` 按算子分别定义。
3. 代入 step 1.6 的候选参数点，验证「选能整除的 `(ℓ, dnum)`」这条建议的定量依据。

**影响**：这条直接决定 **B1 边界的收益是否被最慢 digit 拖累**——而 B1 是 phase3 步 3.3 的核心改造。
现在 3.3 的收益估计（-29%）没有考虑这一项。

### 3.3 流水线并行 + 分层 Roofline

**症状 A（流水线）**：phase4 步 4.1 写着 `117K → 87K cycles`，这个 87K 从哪来的没有记录。
若它是 `max(load, compute, store) × n_limb + 填充`，那就**已经是一个吞吐模型了**，只是没写成式子——
写出来，它就是 §3.1 那个 `max()` 版本在片内的对应物，两者是同一个道理在两级存储上的应用。

**症状 B（Roofline 分层）**：§1.4 的三个 AI 数字**属于三个不同的边界**，画在同一张 roofline 上会得出矛盾结论：

| AI 数字 | 分子（op） | 分母（byte 跨过哪条边界） | 对应的屋顶 |
|---|---|---|---|
| BConv **0.23 MAC/Byte** | `K·M = 15` MAC / 系数 | 片上 AXI：进 3 字 + 出 5 字 | **on-chip AXI 带宽**（512-bit @ 166MHz） |
| B0/B1/B4 **0.32 / 0.89 / 2.1 ops/byte** | 整条 ModUp 的 op | **PCIe**（host ↔ 加速器） | **PCIe 带宽**（~3 GB/s 实测） |
| NTT **`log N / 32`** | 蝶形运算数 | 单 limb 的读写 | 视放在哪级而定 |

**所以必须画分层 Roofline（hierarchical roofline），三条带宽屋顶**：PCIe / HBM / on-chip SRAM-AXI。
L1L2 §2.1 说「BConv 卡 I/O」用的是第三条屋顶；task.yaml §四说「AI 0.32」用的是第一条。
两句话都对，但它们**不是同一个瓶颈**，而现在的笔记里读起来像是同一个。

**这也正是本项目区别于 HERA/CiFlow 的地方**：HERA 假设密文已在 HBM，它的图上没有 PCIe 这条屋顶，
所以它看见的瓶颈是 NTT。把 PCIe 屋顶画出来，才是本项目的 Fig. 1。

**统一口径的三条硬规定（画图前必须先定）**：
1. **分子**：`op` 是按 MAC 计 1 还是按「模乘 + 模加」计 2？（`0.23 MAC/Byte` 与 `0.32 ops/byte` 目前不同源）
2. **分母**：明确标注跨过的是哪条边界，写进变量名，如 `AI_pcie` / `AI_axi`
3. **是否含 evk**：CiFlow 表 II 的 AI **含** evk 流量，本项目当前**不含** → 与文献对比前必须换算
   （task.yaml 1.3 `changes` 已列此项，本表把它升级为口径规定）

**影响**：这三条应写进 [L0_符号表.md](L0_符号表.md) §9，作为 step 1.3/1.4 的强制口径。
