## 0. 三条结论

1. **P3 没有破坏时序。** 6 ns 仍勉强收敛（WNS +0.029 ns），7 ns 有裕量（+0.279 ns）。
   P2+P3 两轮「存储换寻址逻辑」累计只让 WNS 退化 0.049 ns。
2. **HLS 的 LUT 估计严重高估。** HLS 估 +32,589，布线后 CLB LUT 实际只 +921（+0.86%）。
3. **PE=16 起可超过 CPU。** P3 的模型 `T(PE) = 245,760/PE + 35,592`，
   PE=32 时 43,272 周期，按能收敛的 7 ns 换算 303 μs，比 CPU 双线程 463 μs **快 1.53×**。
   这是本项目至今第一个在纸面上能赢 CPU 的配置（仍不含 PCIe 与主机开销）。

## 1. P3 布线后时序

| 情景 | 失败端点 | WNS | 判定 |
|---|---:|---:|---|
| 默认 6 ns | 0 | **+0.029 ns** | 收敛 |
| 6 ns + 0.75 ns uncertainty | 3,140 | **−0.721 ns** | 不过 |
| 7 ns + 0.75 ns uncertainty | 0 | **+0.279 ns** | 收敛 |

Hold 三种情景均为 0 失败、WHS +0.007 ns。

### 与 P1 之前（no_auto）对照

| 情景 | P1 前 | P3 | 变化 |
|---|---:|---:|---:|
| 默认 6 ns WNS | +0.078 ns | +0.029 ns | −0.049 |
| 6 ns + 0.75 裕量 WNS | −0.672 ns | −0.721 ns | −0.049 |
| 6 ns + 0.75 失败端点 | 1,638 | 3,140 | +1,502 |
| 7 ns + 0.75 裕量 WNS | +0.328 ns | +0.279 ns | −0.049 |

**三种情景退化幅度完全一致（−0.049 ns），说明是全局性的轻微劣化，不是某条路径崩了。**
失败端点数翻倍但 WNS 几乎不动，属于「更多路径挤在同一临界值附近」。

### 关键路径已换位置

```
P1 前：poly_buffer_1 → local_in_x
       Data Path Delay 5.618 ns (logic 0.907 / 16.1%,  route 4.711 / 83.9%)
       Logic Levels 0

P3  ：Compute_BConv_Systolic 的 Load_W 循环内部
       p_4_fu_110_reg[1]  →  empty_313_fu_126_reg[22]
       Data Path Delay 5.951 ns (logic 0.515 / 8.7%,  route 5.436 / 91.3%)
       Logic Levels 4 (LUT3 + LUT4 + LUT5 + LUT6)
```

P2 删除 `local_in_x` 之后旧路径确认消失。新瓶颈落在 `Load_W`——一个只有 17 拍、
加载 15 个 BConv 权重的小循环，其寄存器被布得很分散（route 占 91.3%）。
**这是布局问题不是逻辑问题**，与之前那条路径同类：改并行度或逻辑都动不了它，
需要的是约束布局或减少跨区连线。

### 布线后资源

| 资源 | P3 用量 | 器件总量 | 占用 | P1 前 |
|---|---:|---:|---:|---:|
| CLB LUTs | 108,392 | 1,303,680 | **8.31%** | 107,471 (8.24%) |
| CLB Registers | 64,058 | 2,607,360 | 2.46% | 64,062 (2.46%) |
| Block RAM Tile | 272 | 2,016 | 13.49% | — |
| URAM | 96 | 960 | 10.00% | 96 |

**HLS 估计 LUT 147,916 → 180,505（+32,589），布线后实际 107,471 → 108,392（+921）。**
Vivado 把 P2/P3 新增的 bank 选择与写使能 MUX 几乎全部优化掉了。
**推论：用 HLS 的 LUT 估计判断「资源付不付得起」会严重高估代价。**

### 解析式（四点零误差）

```
变换核(PE)  = 24576 / PE + 337        P2 时是 +325，P3 的工作区寻址加了 12 拍
蝶形(PE)    = 2048  / PE + 26         P2 时是 +25
URAM(PE)    = 24 × PE                 与 P2 完全相同
Execute_Transform = 变换核 + 2        ← P2 时是 变换核 + 2,052
```

**最后一行是 P3 的直接证据**：P2 时 `Execute_Transform` 比变换核多 2,052 拍
（即 `TRANSFORM_LOAD` + `TRANSFORM_STORE`），P3 之后只多 2 拍——外围整塔搬运
被彻底删除，在综合报告里可直接读出。

### Amdahl 模型（P3）

```
T(PE) = 245,760 / PE + 35,592          PE=4 代入得 100,422，与 RTL co-sim 实测一致
        └────┬────┘   └───┬───┘
        10 次变换       固定：预缩放 + BConv + AXI + 控制 + 流水线填充
```

|---:|---:|---:|---:|---|
| 4（现状） | 100,422 | 1.00× | 703 μs | 慢 1.52× |
| 8 | 66,312 | 1.51× | 464 μs | **打平** |
| 16 | 50,952 | 1.97× | 357 μs | **快 1.30×** |
| **32** | **43,272** | **2.32×** | **303 μs** | **快 1.53×** |
| ∞（不可达） | 35,592 | 2.82× | — | — |

### 与基于 P2 那一轮（ADR-013）对照

| | P2 | P3 |
|---|---|---|
| 可缩放部分 | 327,680/PE | **245,760/PE**（少了 TRANSFORM_LOAD/STORE 的 81,920/PE） |
| 固定部分 | 38,902 | 35,592 |
| PE=4 总计 | 120,822 | **100,422** |
| PE=32 | 49,082（2.46×） | **43,272（2.32×）** |

**P3 把基线整体压低了，代价是并行度的相对收益变小**——分子小了，分母没怎么变。
这正是 Amdahl 的预期行为，不是 P3 的缺点：**绝对时间是 P3 更快**（43,272 < 49,082）。

## 3. 未决

- **PE≠4 的布线后频率仍然未知。** 本轮只做了 csynth；PE=8/16/32 能否在 7 ns 收敛
  没有证据。上表 @7 ns 一列是**按 PE=4 能收 7 ns 外推的**，不是实测。
- PE=32 时 HLS 估 LUT 754,256（57%）。但本轮已证明 HLS 高估显著，
  实际布线后可能远低于此——**不应据 HLS 估计判定 PE=32 不可行**。
- 新关键路径在 `Load_W`，是布局问题。若要提频，方向是布局约束而非改逻辑。
- INIT 仍为 196,674 周期（`Load_Init_Params`），P1/P2/P3 一拍未动，
  现在已是两 digit 工作量（100,422）的 1.96 倍。分析见
  `doc/INIT_周期构成与三笔可回收开销.md`。
